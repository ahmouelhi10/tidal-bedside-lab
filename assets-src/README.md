# Patient and instrument assets

Source scripts for the realistic patient (`src/web/assets/patient.glb` + `patient.json`) and the instrument set
(`src/web/assets/instruments.glb`). Both are generated. Change the scripts, then rebuild; never hand-edit the GLB files.

| File | What it is |
|---|---|
| `build_patient.py` | MakeHuman/MPFB patient: posed supine, shape keys, baked skin, gown, sheet, COLOR_0, landmark empties, export, check renders |
| `build_instruments.py` | Procedural instruments (no external assets), export, render |
| `build_hands.py` | Gloved MakeHuman right hands posed on each instrument, exported in the instrument frames |
| `renders/` | Check renders: `patient_{male,female}_bmi{17,25,45}.png`, `patient_grid.png`, `patient_landmarks.png`, `instruments.png`, `hands.png` |
| `patient.blend`, `instruments.blend` | Saved scenes from the last build (git-ignored, regenerated by the scripts) |
| `LICENSE-ASSETS.md` | Licence of the assets and exports (CC0) |

## Rebuild

Requires Blender 4.2 LTS, the MPFB 2.0.18 extension (installed from extensions.blender.org) and the MakeHuman system
assets pack (`makehuman_system_assets_cc0.zip`) extracted into MPFB's user data folder
(`%APPDATA%\Blender Foundation\Blender\4.2\extensions\.user\user_default\mpfb\data`). Run from the repository root:

```bash
blender -b --python assets-src/build_patient.py
blender -b --python assets-src/build_instruments.py
blender -b --python assets-src/build_hands.py        # after build_instruments.py (renders read instruments.glb)
```

Add `-- --no-renders --no-blend` to skip the renders and the `.blend` files. The patient build takes about 1.5 min on
a laptop CPU (about 15 s without renders). Do not pass `--factory-startup`, because MPFB needs its saved preferences. The
build is deterministic: it uses fixed macro values and fixed pose angles, and no random numbers.

## patient.glb

**Units and axes:** metres, glTF +Y up. The patient lies **supine**:

- **+X** points toward the head. The crown is at x = 0 and the soles at x ≈ -1.73. Plantar-flexed toes reach -1.80.
- **+Y** is anterior (up, away from the mattress). The back rests on **y = 0**.
- **+Z** is the patient's **left** and **-Z** the patient's **right**. The midsagittal plane is z = 0.

All nodes sit at the origin with identity transforms. Vertices are already in this frame.

**Height:** the model is built at `referenceHeight` = 1.7298 m. Height is **not** a shape key. Scale the whole
patient uniformly by `height / referenceHeight` about the origin (the crown). Uniform scaling also scales BMI:
`BMI(h) = BMI_ref * h / referenceHeight`, so look up the calibration below with
`BMI_ref = BMI_target * referenceHeight / h` (a short obese patient may need `heavy` slightly above 1).

**Pose (applied, no skeleton exported):** head straight, as if on a thin pillow. Arms lie along the body with the palms
toward the mattress. The left arm is abducted 12°. The right arm is abducted 40° onto an arm board, which lies outside
the mattress (z ≈ -0.3 to -0.67). Hips and shoulders are extended per body variant so that the calves, heels,
forearms and hands touch the bed plane. Legs are adducted 4° and externally rotated 8°, and the feet are
plantar-flexed 22°.

| `patient_hair_f` | ~1,100 | `hair_f`: 512 PNG, `alphaMode: MASK` | MakeHuman `braid01`, hair pulled back; the braid's tail under the head and back (x < -0.20 m) is cut away because it is never visible |

**Male and female heads:** `patient_hair` and `patient_eyebrows` are the male set, `patient_hair_f` and `patient_eyebrows_f`
the female set; the app draws the set that matches `female` (0 or 1). `patient_albedo_female.jpg` (beside the GLB, 2048 JPEG,
same UVs as `patient_body`) is the skin baked from MPFB's female textures at the same tone mix; the app swaps it in for a woman.

Total: 33,640 triangles, 5.83 MB. Textures are embedded. There are no tangents (compute MikkTSpace if you need
them) and no skin or animation. Indices are u16/u32 as the exporter chose.

The gown and the sheet are separate nodes, so the app can hide the gown for chest procedures (pads, drains, CPR)
while the sheet keeps the pelvis covered.

### Shape keys (glTF morph targets, `mesh.extras.targetNames`)

Order: `female`, `heavy`, `thin`, `old`, `female_heavy`, `female_thin`, `female_old`. Each target has POSITION and
NORMAL deltas.

| Weight | Set it to |
|---|---|
| `female` | 0 = male, 1 = female |
| `old` | `clamp((age - 25) / 65, 0, 1)` (MakeHuman age 25 to 90 y) |
| `heavy` | BMI above the basis, from the calibration table. 1 = BMI 50 at reference height, for **both** sexes |
| `thin` | BMI below the basis, from the calibration table. 1 = BMI 16 at reference height, for both sexes |
| `female_heavy` | `female * heavy` (corrective) |
| `female_thin` | `female * thin` (corrective) |
| `female_old` | `female * old` (corrective) |

Use either `heavy` or `thin`, never both. The basis is a 25-year-old male, BMI_ref 21.2.

**How the keys were made:** each key is the difference between MPFB bodies built with different macro values, posed
the same way and normalised to the same height. The male-to-female difference is the gender macro going 1 → 0. Old is
age 0.5 → 1.0. Heavy is weight 1, muscle 0, scaled by 1.48 to reach BMI 50. Thin is weight 0, muscle 0, scaled by
0.72 to reach BMI 16. The correctives store the true female-heavy, female-thin and female-old bodies minus the linear
sum (female heavy is scaled by 1.80, female thin by 0.61). For each key, the lowest point of the back stays on y = 0.
Hair, eyebrows and eyes are MPFB-fitted per body, so they follow the head. The gown is re-derived from every body
state with the same cut, smoothing and offset operations, then pushed at least 12 mm off the skin. The sheet is
re-draped on every state by ray casting.

**BMI calibration** (`patient.json` → `bmiCalibration`, at reference height; mass = mesh volume × 1.01 kg/L, a design
value). Interpolate linearly between the 11 weights `0, 0.1, ..., 1`:

| Table | heavy 0 → 1 | thin 0 → 1 |
|---|---|---|
| male 25 y | 21.2, 23.4, 25.7, 28.2, 30.8, 33.6, 36.6, 39.7, 42.9, 46.4, 50.0 | 21.2, 20.7, 20.1, 19.6, 19.0, 18.5, 18.0, 17.5, 17.0, 16.5, 16.0 |
| female 25 y | 20.8, 23.1, 25.5, 28.1, 30.9, 33.8, 36.8, 39.9, 43.1, 46.5, 50.0 | 20.8, 20.2, 19.7, 19.2, 18.7, 18.3, 17.8, 17.3, 16.9, 16.4, 16.0 |

The tables for 90 y (`old = 1`) are in `patient.json` and differ by less than 0.5 BMI.

### COLOR_0 (every mesh, RGBA, unsigned-short normalised)

| Channel | Meaning |
|---|---|
| R | Breathing weight 0..1. Chest and abdomen skin-weight share × anterior-facing factor, smoothed. Displace along the normal by `R * tidal amplitude`. |
| G | Chest-compression weight 0..1. Gaussian (σ 6.5 cm) around the `sternum` landmark, anterior surfaces only, 0 on the arms. |
| B | Region id / 10. Decode with `id = round(B * 10)`. |
| A | 1 |

Region ids: **0** none, **1** head, **2** neck, **3** chest L, **4** chest R, **5** arms (both, split by the sign of z),
**6** abdomen, **7** groin, **8** legs. Regions come from the MakeHuman default-rig skin weights (largest share per
vertex), so the boundaries follow the skinning, not exact anatomy. Hair, eyebrows and eyes are all region 1. The
gown and sheet copy R, G and B from the skin under them; sheet cells that hang off the body are region 7. Interpolated
B between vertices is not an id, so read ids per vertex.

### Landmark empties (16 nodes, named exactly)

Each empty sits on the skin of the basis body (translation in the frame above). It has `extras.anchorVertex` (the
index into `patient_body`'s glTF POSITION accessor whose basis position equals the empty), `extras.blenderVertex`
(the same vertex in the `.blend`) and `extras.region`. **Empties do not morph.** For a morphed patient, read the blended
position of the anchor vertex. `patient.json` → `landmarks` has the same data.

| `leftArm` | left antecubital fossa (-0.580, 0.151, 0.237) |
| `abdomen` | umbilicus, anterior midline at 0.60 × height (-0.692, 0.231, 0) |
| `femoral` | right mid-inguinal point, just below the ligament (-0.847, 0.213, -0.091) |

## instruments.glb

Metres, real size, glTF +Y up. There are 11 top-level mesh nodes at the origin with identity transforms. **The
origin is the working point** (tip, blade tip, pad centre, gauze contact point, tourniquet loop centre), and the
**long axis points along +Y** from that point toward the handle. To place an instrument, put its origin on the
landmark and rotate +Y to the approach direction (for pads, to the outward skin normal). Each node carries `extras`
(`label`, `tip`, `axis`, `length_m`).

## hands.glb

A gloved adult hand per grip: 12 top-level mesh nodes (11 right hands and one left), about 5,400 triangles each, 1.06 MB, no textures. Two
materials: `nitrile_glove` (#4c75d1, roughness 0.55: nitrile is satin) and `gown_sleeve` (pale blue). The app draws the glove
with a nitrile shader (fine stipple, slight translucency) and the sleeve with the fabric shader. The hand is the
MakeHuman/MPFB base-mesh right hand (sex-neutral adult, glove size about 7.5 to 8). It is posed with the MakeHuman
default rig: fingers are curled, or driven by a small CCD IK onto contact points of the instrument. It is then frozen,
smoothed (nails and skin creases removed), thickened 0.7 mm, and given the nitrile's own folds: a 0.7 mm crease on the
inside of each bent finger joint (deeper the more the joint is bent) and soft ridges where the glove is rucked up between
the wrist and the cuff. It then gets a rolled glove cuff and a 34 cm gown sleeve that reaches the elbow, so its end never
shows in a close-up: the cloth bunches where the cuff pushes it up, then has soft folds, widens 2.4 cm toward the elbow
and closes in a gathered, rounded hem. Both follow the forearm's own cross-section.

**Frame: each hand is already placed in its instrument's frame** (metres, glTF +Y up), so draw it with exactly the
instrument's model matrix. The instrument's origin is its working point and +Y points toward its handle (see
instruments.glb above). The node transform is identity.

| Node | Instrument frame | Grip |
|---|---|---|
| `hand_syringe` | `syringe` | thumb on the plunger, index and middle fingers hooked over the flange |
| `hand_ivCannula` | `ivCannula` | pencil (tripod) grip on the hub and flash chamber, thumb and index |
| `hand_needle14G` | `needle14G` | pencil grip on the hub and flash chamber |
| `hand_scalpel` | `scalpel` | table-knife grip, index on the back of the blade, handle end in the palm |
| `hand_forcepsGauze` | `forcepsGauze` | thumb and ring finger in the rings |
| `hand_chestDrain` | `chestDrain` | palmar (fist) grip around the tube 15 cm from the tip, thumb side toward the tip |
| `hand_bougie` | `bougie` | pencil grip 12 cm from the tip |
| `hand_defibPadRight` | `defibPadRight` | flat palm on the back of the pad, fingers spread toward the pad's -X (away from the lead) |
| `hand_stethoscope` | `stethoscope` | palm over the chest piece, fingertips steadying the rim, tubing back between the fingers |
| `hand_usProbe` | `usProbe` | palmar grip around the body, lens below the little finger, thumb on the marked side |
| `hand_press` | its own | flat palm: origin = palm centre on the skin, +Y = back of the hand (outward normal), fingers along +X |
| `hand_pressL` | its own (same as `hand_press`) | **left** hand resting flat beside a puncture or incision, thumb and index spread to tense the skin: the right-hand pose mirrored across the fingers (glTF z -> -z) |

The forearm leaves each hand at a natural angle: wrist extended 32 degrees for the flat-palm grips (22 for the left hand)
and 8 to 14 degrees for the others, except the 14G needle, which is held with the wrist flexed 10 degrees so that a needle
square to the chest has the forearm about 33 degrees above the skin, not raised high. The app reads which way each
forearm leaves (the sleeve's centroid across the instrument axis) and turns rotationally symmetric instruments about their
axis so the arm comes from the operator's side. The two pads are identical, so `defibPadLeft` can use `hand_defibPadRight` drawn with the
left pad's matrix. Each node has `extras`:
`instrument`, `grip`, `frame`. Fingers touch the instrument within a few millimetres. The IK residuals printed by
the build are 0 to 26 mm; the larger ones are fingers that only rest near the shaft (middle finger in the pencil grip,
index on the forceps shank, flat thumbs).
